# LTS Registro Viaggi — Buste paga nel profilo
18 novembre 2026 · PR di sviluppo · NON PUBBLICATO

## Integrazione
- Profilo autista → I MIEI DOCUMENTI → CEDOLINO / CU / ALTRI DOCUMENTI.
- Pagina amministrativa separata: /LTS-Registro-Viaggi/paghe-amministrazione/
- Accesso via telefono/password LTS con verifica MFA TOTP obbligatoria anche dopo accessi alla dashboard principale.
- Upload PDF multipli, con identificazione manuale per ciascun file; nessun abbinamento per nome/OCR.
- I PDF restano in bozza fino a pubblicazione confermata. Revoca successiva disponibile.
- Sincronizzazione per account: backend centralizzato Supabase, refresh alla riapertura, ritorno in foreground e ogni 60 secondi mentre la finestra dei documenti è aperta.
- Nessun servizio di push dedicato implementato.

## Perimetro della protezione
- Tabelle private public.lts_payroll_documents e public.lts_payroll_audit con RLS forzata.
- Bucket Storage lts-payroll-private; nessun accesso anon/authenticated diretto.
- Unica Edge Function lts-payroll; chiave servizio esclusivamente sul server.
- Ogni chiamata verifica JWT presso Supabase Auth, sessione in corso, account attivo, ruolo.
- Ogni chiamata amministratore impone fattore TOTP già registrato e aal2 nel JWT.
- Dipendente vede/ottiene solo file pubblicati per il proprio UUID di account.
- PDF non presenti nel repository, CDN pubblico, cache PWA, backup viaggi o IndexedDB.
- Download eseguito tramite Edge Function con bearer nell'header, mai nella URL.
- Log privato dei caricamenti, delle transizioni di stato e dei download.
- Pubblicazione e audit avvengono in un'unica transazione SQL.
- File PDF massimo 8 MiB, firma PDF verificata, caricamento senza sovrascrittura.

## Verifiche prima di una pubblicazione
1. Eseguire le verifiche statiche CircleCI (node --check e node --test tests/*.test.mjs).
2. QA Supabase ISOLATO: applicare la migration e distribuire la nuova Edge Function solo in ambiente di prova; non modificare funzioni Booking TFG o account esistenti.
3. Valutare l'origin CORS in staging, senza consentire origini arbitrarie in produzione.
4. Creare due dipendenti di prova A/B e un amministratore con MFA e documenti PDF fittizi.
5. Test NEGATIVI: assenza JWT, JWT non valido, sessione revocata, amministratore senza MFA, autista che indovina ID dell'altro, dipendente disattivato, bozza, documento revocato, CORS da altra origine, file non PDF, PDF troppo grande, payload malformato.
6. Test POSITIVI: un PDF per categoria, più PDF nello stesso caricamento, bozze nascoste, conferma individuale, download PDF, due dispositivi dello stesso autista, aggiornamento su ritorno foreground/60s, upload ripetuti e ripresa dopo errori di rete.
7. Validare privacy GDPR, tempi di conservazione, backup/restore, modalità di rilascio agli ex-dipendenti e autorizzazioni delle persone abilitate a leggere cedolini. Consultare consulente del lavoro/DPO.
8. Soltanto dopo esito positivo, applicare migration su produzione, distribuire la funzione e fare una sola pubblicazione controllata della PR. Nessun bypass MFA/JWT, nessun cambio ai Porti, Booking TFG, KV, cron, tariffario o PDF del Registro.

## Fuori dal perimetro
Nessun calcolo paghe, TFR o contributi; nessuna generazione CU; niente OCR di identificazione automatico; notifiche push e firma delle consegne rimandate. Non trattare i dati dimostrativi come documenti effettivi.
